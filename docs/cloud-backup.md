# Cloud Backup

Opt-in backup of the full PennyWise backup (the same bytes `BackupExporter`
writes for a local `.pennywisebackup`) to **Google Drive** (standard flavor
only) or **WebDAV** (both flavors). Off until the user connects a provider.

The local backup format is unchanged; see [backup-format.md](backup-format.md).
Cloud backup wraps that JSON in an encrypted envelope and nothing else.

## Guarantees

- **Never plaintext.** `CloudBackupManager.backupNow()` is the only upload
  path and always seals with `CloudBackupCrypto` first (it also asserts the
  envelope magic before upload). There is no "encryption off" switch.
- **Providers are dumb.** `CloudStorageProvider` stores and retrieves an
  opaque file. Export/import rules stay in `BackupExporter`/`BackupImporter`
  (`importBackupBytes` is the in-memory twin of `importBackup(uri)`).
- **Secrets fail closed.** WebDAV URL/username/password, the Drive account
  name and the passphrase are sealed with an AES-256-GCM Android Keystore key
  (`AndroidKeystoreSecretCipher`, bound to the entry name as GCM AAD) and kept
  in `cloud_backup_secrets` prefs. If sealing or opening fails,
  `CloudSecretStore` throws `SECURE_STORAGE_UNAVAILABLE`; it never falls back
  to plain preferences. No OAuth token is stored: Play services caches the
  Drive grant and issues short-lived tokens on demand.
- **No secrets or paths in logs.** Errors are a closed `CloudBackupError`
  enum; logs and the persisted "last error" carry only the code.
- **Excluded from Android backup / device transfer** (`data_extraction_rules.xml`,
  `backup_rules.xml`): a new phone starts disconnected.

## Envelope v1

| Offset | Size | Field |
|---|---|---|
| 0 | 4 | magic `PWCB` |
| 4 | 1 | envelope version = 1 |
| 5 | 1 | KDF id = 1 (PBKDF2-HMAC-SHA256) |
| 6 | 4 | iterations (u32 BE), default 600,000 |
| 10 | 1 | payload = 1 (gzip of the PennyWise backup JSON) |
| 11 | 16 | random salt |
| 27 | 12 | random GCM IV |
| 39 | … | AES-256-GCM ciphertext ‖ 128-bit tag |

The 39-byte header is GCM associated data, so the version, KDF parameters,
salt and IV are authenticated. Decryption accepts 100,000–10,000,000
iterations (no downgrade, no stall), caps the download at 256 MiB and the
decompressed payload at 512 MiB, and returns nothing unless the tag verifies:
a wrong passphrase and a tampered/truncated file both fail before import.

**KDF choice:** PBKDF2-HMAC-SHA256 at the OWASP 2023 level (600k). Argon2id
would resist GPUs better but needs a native/Bouncy Castle dependency; PBKDF2
ships with Android 8+ and the JVM. To strengthen later, add a new KDF id or
raise the count — old files stay readable because the parameters are in the
header. `CloudBackupCryptoTest.knownAnswer_v1EnvelopeStillOpens` pins a v1
fixture generated by an independent implementation; never change it.

**Passphrase:** at least 10 characters, stored on the device (Keystore-sealed)
so scheduled backups can run. It protects the cloud copy from the provider,
not from someone using the unlocked phone. Lost passphrase = unrestorable
backups; the UI says so. Changing it doesn't re-encrypt old snapshots; restore
asks for the passphrase when the stored one doesn't open a snapshot.

## Snapshots, retention, schedule

- Names: `pennywise-backup-<yyyyMMddTHHmmssZ>-<6 hex>.pwenc` (UTC). The random
  suffix keeps two devices from overwriting each other; ordering comes from
  the name, not provider metadata. Only matching names are listed, restored
  or deleted.
- Retention (keep last N = 3/5/10/20, default 5) runs after each successful
  upload, never deletes the snapshot just uploaded, and counts every
  PennyWise snapshot in the folder (all devices sharing it).
- WebDAV uploads to `<name>.part` and `MOVE`s it into place, so an interrupted
  upload never looks like a snapshot. Drive uses a single multipart request.
- Automatic backup: `CloudBackupWorker`, periodic daily/weekly, requires a
  network and battery-not-low, exponential backoff, at most 3 attempts for
  network/server errors; auth/passphrase errors stop immediately and show as
  "Last attempt failed" on the screen.
- Restore: pick a snapshot → choose **Merge** or **Replace** (Replace needs a
  second, destructive confirmation) → download → decrypt → import.

## Providers

### WebDAV (both flavors)
`https://` only; URLs with embedded credentials, queries or fragments are
refused. Basic auth. Redirects are never followed (credentials stay on the
host the user typed). Files live in `<base>/PennyWise/`.

### Google Drive (standard flavor only)
`PlayGoogleDriveFeature` (in `app/src/standard`) uses the Play services
Authorization API (`play-services-auth`, `standardImplementation`) with only
the `https://www.googleapis.com/auth/drive.appdata` scope; files live in the
hidden `appDataFolder`. The F-Droid flavor binds `UnavailableGoogleDriveFeature`
and has no Google dependency. Disconnect revokes the grant.

#### One-time owner setup (required before Drive works)
No client ID or secret is in the repo or the app; Google matches the app by
package name + signing certificate.

1. In [Google Cloud Console](https://console.cloud.google.com/), create or
   pick a project and **enable the Google Drive API**.
2. Configure the **OAuth consent screen** (External, app name, support email,
   privacy policy URL). Add the scope `.../auth/drive.appdata` (a non-sensitive
   scope). Publish it, or add testers while in Testing.
3. **Credentials → Create credentials → OAuth client ID → Android**, once per
   signing key:
   - Package `com.pennywiseai.tracker`, SHA-1 of the release keystore
     (`keytool -list -v -keystore <release.jks> -alias <alias>`).
   - If the Play build is signed by **Play App Signing**, also add the SHA-1
     from Play Console → Setup → App signing.
   - For debug builds: package `com.pennywiseai.tracker.debug` and the debug
     keystore SHA-1 (`keytool -list -v -keystore ~/.android/debug.keystore -storepass android`).
4. No code change is needed. Until this is done, connecting shows
   "Google Drive backup isn't set up for this build" (`DEVELOPER_ERROR` →
   `DRIVE_NOT_CONFIGURED`; a 403 `accessNotConfigured` from the Drive API maps
   to the same message).
